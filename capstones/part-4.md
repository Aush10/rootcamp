**Status:** NOT STARTED  
**Rule:** capstone must be demonstrated as functioning **within its defined learning scope** before advancing to Part graduation.  
**Notes:** open-note allowed; retries documented; learner is the implementer, and may not use AI-generated code before P3M3.

## Deliverables / observable behaviors

- Verify the precise Hermes framework/version and the provenance of installed components.
- Assemble restricted tool wrappers, read-only indexed access to notes and synthetic catalogue, source attribution and controlled memory.
- Connect the defensive browser suite and selected prebuilt tools behind explicit scopes and audit trails.
- Demonstrate bounded context, private identity-based access, a reversible local/cloud configuration and a securely connected Android-facing interface.
- Show failure recovery, backup/restore, graceful tool denial and human takeover.
- No public raw shell, desktop session, database admin endpoint or unrestricted VM access.
- The learner explains the mechanism of each integration and can identify when an AI instruction must not be executed.

## Submission package

- Learner's own explanation of the system and decisions
- Evidence folder or a clear commit reference
- Test plan, reproducible test output and failure/recovery notes
- Source citations in the SQL tree when appropriate
- Security-gate decision and retest evidence, if applicable
