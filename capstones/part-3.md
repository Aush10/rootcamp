# PART 3 CAPSTONE — Controlled Autonomy — secured AI shop demonstrator

**Status:** NOT STARTED  
**Rule:** capstone must be demonstrated as functioning **within its defined learning scope** before advancing to Part 4.  
**Notes:** open-note allowed; retries documented; learner is the implementer, and may not use AI-generated code before P3M3.

## Deliverables / observable behaviors

- Run a **simulated** storefront/order workflow using fictional products and test doubles for suppliers, printers and shippers.
- Explain AI permissions, tool contracts, prompt trust boundaries, API key handling, cost controls, and human approval points.
- Show safe tests for malicious instructions/input, package risks, invalid tool arguments and disabled commands.
- Demonstrate logs, manual override, rollback, explicit refusal/denial and separation of private information.
- Show that AI cannot independently create real charges, refunds, ad spend, shipping orders or account changes.
- The system is judged as a **security learning instrument**, not on profit or sales volume.
- Human assessor verifies traces and failure recovery before allowing Hermes tooling.

## Submission package

- Learner's own explanation of the system and decisions
- Evidence folder or a clear commit reference
- Test plan, reproducible test output and failure/recovery notes
- Source citations in the SQL tree when appropriate
- Security-gate decision and retest evidence, if applicable

## Evaluation and demonstration

The exact demonstration script and module-specific standards will be agreed during this part. A polished presentation is optional; **function, explanation, reproducibility and relevant safety** are essential.

**Noncritical gap:** log for follow-up.  
**Blocking gap:** required operation not demonstrated, or a critical safety boundary failed. Fix and retest.
