# Module 1.1 — Open-note assessment plan

**Status:** DRAFT; tune it together at the end of the module  
**Type:** mixed concept check + evidence walkthrough  
**Grade method suggestion:** 0–100 for understanding, plus non-numeric safety corrections  
**Safety priority:** normal, except unsafe file downloads/extensions or accidentally shared sensitive data must be corrected

## Prompt

Using only the files you made and your open notes, demonstrate:

1. **HTML/CSS (20):** Identify an HTML element, a CSS selector, and one observed style change. Explain the DOM simply.
2. **SQLite (20):** Explain table, row, field, primary key; retrieve at least one row with a query you wrote.
3. **Tool literacy (15):** Identify the difference between Microsoft 365, Google Workspace and a local file, without pretending every tool is interchangeable.
4. **Browser / extension literacy (15):** Explain what permissions an extension may request and why unnecessary permissions are dangerous.
5. **HTTPS / fingerprint (20):** Describe in plain language what TLS is trying to protect and what a certificate thumbprint identifies; do not claim a thumbprint is a password.
6. **Reproducibility (10):** Show where your files and notes live and explain how you would reopen the project.

## Evidence and grading

Evidence may be screenshots, text, demonstration, or a short written explanation; code aesthetics do not count at this level. Open-note means source material, notes and official references are allowed. The submitted files must be the learner's work. The reviewer asks follow-up questions if an explanation is memorized but not understood.

- 85–100: demonstrated and explained cleanly
- 70–84: functional, limited gaps documented
- below 70: revisit only the missing concepts and repeat the relevant checks

This threshold is a **proposal**, not a rigid punishment; security-critical unsafe actions must be corrected even if the total is high.
