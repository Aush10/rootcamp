# Module 2.4 — Open-note assessment plan

**Status:** PROPOSAL — agree on exact assessment when the module begins  
**Format idea:** mandatory hosting and secret audit  
**Criticality:** SECURITY GATE — must fix before proceeding  
**Timebox:** included in or appended to the module's 8+ h target

## Evidence prompt

Show staged website architecture and hand-built local SQL lookup. Inspect listener scope, credentials, sharing, and rollback; fix critical exposures before continuing.

## Suggested scoring

Choose **one** appropriate measure for this module, not all:
- Demonstration checklist: `complete / partial / revisit` with evidence pointers
- Practical build test with observed pass/fail and a retry log
- Open-note written or oral reasoning scored with a small 0–100 rubric
- Repository review based on submitted files and reproducibility

**Not every error blocks progress.** Noncritical gaps become backlog entries. A safety-critical flaw, missing capstone behavior, or dangerous permissions must be fixed and retested before crossing the applicable gate.

## Reviewer procedure

1. Read the learning outcomes and submitted evidence.
2. Reproduce or inspect evidence without executing untrusted code on a personal machine.
3. Identify confirmed issues separately from guesses and preferences.
4. State the minimum change required (no generated replacement code before P3M3).
5. Allow retry with a short revision record.

**Assessment is open-note.** Notes, previous labs and official documentation are permitted. Before P3M3, AI is permitted as an instructor/reviewer of completed work, not as a coder, completer or patch generator.
